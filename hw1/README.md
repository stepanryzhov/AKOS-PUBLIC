# Электронный аукцион

Последовательная имитация на C для Linux. Используются libc и POSIX:
`open`, `read`, `close`, `dprintf`, `sigaction`, `nanosleep`.

## Сборка и запуск

```sh
make
./auction
./auction -f data/default.txt -l result.log -d 0
./auction -f tests/data/reserves.txt -r 1 -l hold.log -d 0
make test
```

Нужны компилятор C и `make`.
Без `-f` запускается встроенный пример, совпадающий с `data/default.txt`.
`-l` задаёт файл лога (по умолчанию `auction.log`, перезаписывается).
В лог попадают те же события и итоги, что и в консоль.
Входной файл и файл лога должны иметь разные имена.
`-d` задаёт задержку отображения между тактами: 0–10000 мс,
по умолчанию 200 мс. Эта задержка не влияет на результат модели.
`-h` выводит справку.
`-r` задаёт правило резервирования: `0` (по умолчанию) — резерв только у
текущего лидера; `1` — резервы прежних лидеров сохраняются до закрытия раунда.
Этот входной параметр задаётся в командной строке при любом способе загрузки
данных; формат числового файла остаётся прежним. Другие значения `-r` отклоняются.

Ctrl+C или SIGTERM отменяют незавершённые лоты, освобождают резервы
и сохраняют итоги. Уже оплаченные покупки остаются в силе.
Коды выхода: 0 — обычное завершение, 1 — ошибка,
130 — SIGINT, 143 — SIGTERM.

## Входной файл

Файл содержит только целые числа, разделённые пробелами или переводами строк.
Предполагается, что данные введены корректно и соответствуют таблице ниже.
Проверяется только число участников и лотов, чтобы не выйти за размеры массивов.

Чтение устроено по примеру из презентации: `open` открывает файл, `read`
читает его в буфер, `close` закрывает. Затем `strtol` разбирает числа в буфере.
Используется небольшой обычный текстовый файл, не более 16383 байт.

```text
2 1 1 2 1
100 0 1 0
150 1 2 1
20 10 5
```

Первая строка: число участников, число лотов, одновременно открытые лоты,
продление, правило отказа. Затем для каждого участника: бюджет, стратегия,
задержка ставки, отказ. Затем для каждого лота: начальная цена, шаг, длительность.

| Параметр | Значения |
| --- | --- |
| Число участников и лотов | 1–32 |
| Одновременно открытые лоты | 1–число лотов |
| Бюджет, начальная цена | 0–1000000 целых денежных единиц |
| Минимальный шаг | 1–1000000 |
| Длительность, задержка подготовки ставки | 1–1000 тактов модели |
| Интервал продления | 0–1000 тактов, 0 отключает продление |
| Стратегия | 0 — текущая цена + шаг, 1 — текущая цена + два шага |
| Правило отказа | 0 — все оплачивают; 1 — возможен отказ с повторным открытием |
| Правило резервирования (`-r`) | 0 — только текущий лидер; 1 — удержание до закрытия раунда |
| Отказ участника | 0 — оплачивает, 1 — отказывается при правиле отказа 1 |

## Правила модели

- Аукционист открывает лоты по порядку, соблюдая ограничение их числа.
  Каждый участник и каждый лот представлены отдельной структурой.
- Участник выбирает первый открытый лот, пропуская лоты, где уже лидирует
  или исключён после отказа. Одновременно он готовит одну ставку.
  Сумма определяется при подготовке, а проверяется при поступлении:
  за время задержки цена может измениться. Непосильные ставки отклоняет аукционист.
- Первая ставка также должна быть не меньше начальной цены плюс шаг.
  В обоих режимах полная сумма ведущей ставки резервируется.
  При `-r 0` резерв прежнего лидера освобождается сразу при смене лидера.
  При `-r 1` он удерживается до закрытия текущего раунда; на каждом лоте
  у участника хранится резерв только его последней принятой ставки.
  Свободные деньги равны бюджету минус резервы по всем лотам. Для повышения
  своей прежней ставки в том же лоте можно использовать уже внесённый резерв:
  новая сумма заменяет старую, дополнительно резервируется только разница.
  Деньги, зарезервированные в другом лоте, использовать нельзя.
- В один момент времени сначала закрываются лоты, затем поступают ставки
  по номерам участников, открываются ожидающие лоты и готовятся новые заявки.
  Ставка ровно в момент закрытия опаздывает. После обработки такта время
  увеличивается на единицу: `0, 1, 2, ...`.
- При принятии ставки в конце торгов срок закрытия увеличивается до
  `текущее время + интервал продления`, если это позже прежнего срока.
- При закрытии раунда освобождаются все резервы этого лота, включая резервы
  проигравших, и только победитель оплачивает покупку.
  При отказе победителя деньги не списываются, все резервы раунда освобождаются,
  лот открывается с начальной ценой на полную длительность. Отказавшийся
  исключается из этого лота. Заявки предыдущего раунда отклоняются.
  Благодаря исключению повторные открытия не могут продолжаться бесконечно.
- Лот без принятых ставок закрывается непроданным. Программа завершается,
  когда все лоты закрыты и расчёты завершены. Подготовленные заявки,
  ещё не поступившие к этому моменту, больше не обрабатываются.

Случайности нет: одинаковые параметры дают одинаковый журнал событий.

## Запуск тестовых примеров

`make test` запускает шесть исходных примеров командами из `Makefile`, затем
`tests/check.sh`: встроенный и файловый примеры, второй режим резервирования,
отказ при удержании резервов и SIGINT/SIGTERM для обоих режимов. Для тестов
нужны стандартная оболочка `sh` и обычные утилиты `grep`, `awk`, `cmp`, `mktemp`,
`sleep`; Python не требуется.
Проверяются ожидаемые строки, порядок освобождения резервов, коды завершения
и совпадение консольного вывода с логом. При несовпадении `make` останавливается
с ошибкой. При успехе выводится «Все тесты пройдены».

| Пример | Ожидаемый результат |
| --- | --- |
| `reserves` | Лот 1 покупает участник 1 за 60, лот 2 — участник 2 за 50; есть отклонения из-за нехватки доступных денег |
| `unsold` | Оба лота не проданы |
| `deadline` | Ставка в момент закрытия отклонена, лот не продан |
| `extension` | Торги продлеваются, участник 2 покупает лот за 110 |
| `refusal` | После отказа участника 1 лот покупает участник 2 за 20 |
| `all_refuse` | После отказа единственного участника лот остаётся непроданным |
| `hold_reserves` (`reserves.txt`, `-r 1`) | Лот 1 покупает участник 2 за 70, лот 2 — участник 1 за 40. До закрытия резервы проигравших удерживаются, в итогах все равны нулю |
| `hold_refusal` (`-r 1`) | После отказа участника 1 освобождаются резервы обоих участников. Во втором раунде лот покупает участник 2 за 20 |

Каждый запуск `make test` создаёт или обновляет все журналы из отчёта:
`tests/default.log`, `tests/interrupt.log`, `tests/terminate.log`,
`tests/hold_reserves.log`, `tests/hold_refusal.log`, `tests/hold_interrupt.log`,
`tests/hold_terminate.log`, а также логи шести исходных примеров.
Встроенный пример сравнивается с `data/default.txt` целиком.
Проверки сигналов ждут появления резерва (при `-r 1` — резерва прежнего лидера),
затем посылают сигнал и проверяют коды 130/143, отмену лотов, неизменные бюджеты
и нулевые резервы. `make clean` удаляет созданные логи; `make test` восстанавливает их.

## Файлы

- `src/main.c` — аргументы запуска, сигналы, вывод в консоль и лог.
- `src/config.c` — чтение параметров, встроенный пример.
- `src/auction.c`, `src/auction.h` — сущности и последовательная модель.
- `tests/data` — тестовые данные; команды их запуска находятся в `Makefile`
  и `tests/check.sh`.

Отчёт по заданию находится в файле `report.pdf`.
