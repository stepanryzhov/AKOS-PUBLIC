# Электронный аукцион - задание 2

Многопоточная версия предыдущего проекта на C для Linux.

## Сборка и запуск

```sh
make
./auction
./auction -f data/default.txt -l result.log -d 20
./auction -f tests/data/reserves.txt -r 1 -l hold.log -d 20
make test
```

Нужны компилятор C, `make` и библиотека `pthread`. При сборке используется
ключ `-pthread`. Дополнительные библиотеки не требуются.

- `-f` - входной файл. Без него используются встроенные данные из `data/default.txt`.
- `-l` - файл лога, по умолчанию `auction.log`. Файл перезаписывается.
- `-d` - пауза между тактами в миллисекундах, от 0 до 10000.
  По умолчанию 200 мс. Значение 0 включает быстрый режим с паузой 1 мс.
- `-r 0` - резерв только у текущего лидера, это режим по умолчанию.
- `-r 1` - резервы прежних лидеров удерживаются до закрытия раунда.
- `-h` - справка.

В консоль и лог записываются одинаковые события и итоги одного запуска.
Входной файл и лог должны иметь разные имена.

## Потоки и синхронизация

Для каждого участника и каждого лота создаётся отдельный поток.
Ещё один поток выполняет роль аукциониста. Основной поток увеличивает
счётчик тактов, следит за прерыванием и дожидается остальных через `pthread_join`.
Всего получается `число участников + число лотов + 2` потока,
включая основной. Для встроенных данных это 8 потоков.

Участник выбирает открытый лот и готовит одну ставку. Когда наступает
время её передачи, поток ставит флаг `ready` и вызывает `sem_post`.
Пока аукционист не обработал заявку, участник не меняет её.

Поток лота следит за сроком закрытия. Когда срок истёк, он ставит
`close_requested` и тоже уведомляет аукциониста через `sem_post`.
Срок читается заново, поэтому учитываются продления и повторные открытия.

Аукционист ждёт события через `sem_wait`. Затем обрабатывает запросы
закрытия, готовые ставки и открывает ожидающие лоты при наличии мест.
Только аукционист принимает ставки, меняет резервы, определяет победителей
и списывает оплату.

Общие данные и вывод защищены одним `pthread_mutex_t`. Проверка суммы,
бюджета, срока и изменение состояния ставки происходят под одним мьютексом.
Это предотвращает двойную оплату и одновременное расходование одних денег
на разных лотах. Семафор служит уведомлением о работе, мьютекс защищает данные.

Используется один POSIX-семафор: `sem_open`, `sem_post`, `sem_wait`,
`sem_close`. Его имя содержит PID и удаляется через `sem_unlink` сразу
после открытия. Такой вариант работает и в Linux, и в macOS.

Участники и лоты независимо проверяют своё состояние с паузой 1 мс;
мьютекс во время паузы не удерживается. Общего пошагового запуска потоков
или барьера нет. Это простой вариант для небольшого учебного проекта,
максимум для 32 участников и 32 лотов.

## Время и порядок событий

Модельное время - обычный счётчик: `0, 1, 2, ...`. Основной поток делает
паузу `-d`, затем увеличивает счётчик на единицу под мьютексом.
Участники и лоты читают этот же счётчик под мьютексом.
Пока аукционист обрабатывает события, значение счётчика не меняется.
Точная длительность работы не измеряется: все сроки заданы в тактах модели.
Ставка принимается только при `текущее время < срок закрытия`.
Даже если поток лота ещё не успел запросить закрытие, просроченная ставка
отклоняется. Заявка предыдущего раунда также отклоняется.

Порядок передачи заявок зависит от планировщика потоков. Победители,
число ставок и журнал разных запусков могут отличаться даже при одинаковых
данных. В быстрых торгах влияние планировщика заметнее. Для наглядного
запуска удобнее `-d 200`, для проверок используется `-d 20`.

## Входной файл

Файл содержит целые числа, разделённые пробелами или переводами строк:

```text
2 1 1 2 1
100 0 1 0
150 1 2 1
20 10 5
```

Первая строка: число участников, число лотов, одновременно открытые лоты,
интервал продления, правило отказа.
Затем для каждого участника: бюджет, стратегия, задержка ставки, отказ.
Затем для каждого лота: начальная цена, шаг, длительность торгов.

| Параметр | Значения |
| --- | --- |
| Число участников и лотов | 1-32 |
| Одновременно открытые лоты | 1-число лотов |
| Бюджет, начальная цена | 0-1000000 |
| Минимальный шаг | 1-1000000 |
| Длительность торгов, задержка ставки | 1-1000 тактов |
| Интервал продления | 0-1000 тактов; 0 отключает продление |
| Стратегия | 0 - один шаг; 1 - два шага |
| Правило отказа | 0 - все платят; 1 - отказ с повторным открытием |
| Отказ участника | 0 - платит; 1 - отказывается при включённом правиле отказа |

Проверяются диапазоны, наличие всех чисел и отсутствие лишних данных.
Размер файла должен быть меньше 16383 байт.
Файл читается через `open`, `read`, `close`, числа разбираются `strtol`.

## Правила торгов

- Участник выбирает первый открытый лот, где он не лидирует и не исключён
  после отказа. Одновременно готовится одна ставка.
- Сумма фиксируется при подготовке: текущая цена плюс один или два шага.
  К моменту поступления другая ставка может сделать эту сумму недостаточной.
  Непосильные заявки также передаются аукционисту и отклоняются.
- Первая ставка должна быть не меньше начальной цены плюс минимальный шаг.
- Полная сумма ведущей ставки резервируется. При `-r 0` прежний лидер
  получает резерв обратно сразу; при `-r 1` он удерживается до закрытия раунда.
- Доступные деньги для ставки равны бюджету минус все резервы плюс
  собственный резерв в этом лоте. Новая сумма заменяет прежний резерв,
  поэтому при повышении дополнительно блокируется только разница.
- Принятая ставка продлевает торги до `текущее время + интервал продления`,
  если этот срок позже прежнего.
- При закрытии освобождаются все резервы лота и победитель оплачивает покупку.
  При отказе деньги не списываются, отказавшийся исключается из этого лота,
  лот повторно открывается с начальной ценой и полной длительностью.
- Если ставок нет, лот остаётся непроданным. Повторные открытия конечны:
  каждый отказ исключает ещё одного участника.

## Завершение

Обычно программа завершается после закрытия всех лотов и расчётов.
Ctrl+C или SIGTERM отменяют незавершённые лоты, освобождают их резервы
и сохраняют итоги. Уже оплаченные покупки остаются в силе.

Сигналы получает основной поток. Обработчик только сохраняет номер сигнала.
Основной поток меняет флаг остановки под мьютексом и будит аукциониста через
семафор. Затем все потоки завершаются и присоединяются через `pthread_join`.
Семафор, мьютекс и файл лога освобождаются после завершения потоков.
Если создать один из потоков не удалось, уже созданные тоже останавливаются.

Коды выхода: 0 - обычное завершение, 1 - ошибка,
130 - SIGINT, 143 - SIGTERM.

## Проверки

`make test` запускает `tests/check.sh`. Нужны `sh`, `grep`, `cmp`,
`mktemp` и `sleep`; Python не требуется.

Проверяются встроенные данные и тестовые файлы в обоих режимах резервирования,
торги без покупателя, ставка на границе закрытия, продление, отказ победителя,
повторные быстрые запуски, 32 участника и 32 лота, некорректные параметры,
SIGINT/SIGTERM и сохранение уже оплаченной покупки при прерывании.

Проверки написаны в одном shell-скрипте: `grep` ищет ожидаемые события и итоги,
`cmp` сравнивает консоль и файл лога. Для простого примера с одним участником
проверяются победитель, цена 15, единственная оплата, остаток бюджета 85
и выручка 15 в обоих режимах резервирования. Для всех запусков проверяются
наличие итогов и отсутствие положительного остаточного резерва.
В примерах с несколькими участниками точные победители не фиксируются,
так как зависят от порядка потоков. Ожидание ограничено для обнаружения зависаний.
Подробной проверки каждой ставки, срока и изменения резерва по журналу нет.

Журналы обычных примеров записываются в `tests/*_r0.log` и `tests/*_r1.log`,
журналы прерываний - в `tests/signal_*.log`. `make clean` удаляет сборку и логи.
