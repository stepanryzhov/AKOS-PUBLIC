## Сборка

Нужны Linux, компилятор C, `make`; для тестов - Python 3.
Используются libc и POSIX API, ключи линковки `-pthread -lrt`.
Команды выполняются из папки `hw3`.

```sh
make
./auction_named -f tests/data/simple.txt -d 100 -l simple.log
make test
```

Результат простого примера: победитель 1, цена 15, остаток бюджета 85, резерв 0.
Без `-f` используются встроенные данные, соответствующие `data/default.txt`.

## Варианты и запуск

| Требования | Программы | Взаимодействие |
| --- | --- | --- |
| 4-5 баллов | `auction_named` | `fork`, именованные POSIX-семафоры, разделяемая память POSIX |
| 6 баллов | `auction_unnamed` | `fork`, безымянные POSIX-семафоры в разделяемой памяти |
| 7-8 баллов | `auctioneer`, `participant`, `lot` | Независимый запуск, именованные семафоры и разделяемая память |
| Выше 8 баллов | `auctioneer_mq`, `participant_mq`, `lot_mq` | Независимый запуск, именованный семафор и POSIX-очереди сообщений |

Аукционист, каждый участник и каждый лот - отдельные процессы.
Всего `N + M + 1` процессов. Первые два варианта запускают рабочих автоматически:

```sh
./auction_named -f data/default.txt -d 100 -l named.log
./auction_unnamed -f data/default.txt -r 1 -d 100 -l unnamed.log
```

Независимый вариант запускается в трёх терминалах. Сначала аукционист,
затем после сообщения `Ожидание процессов` - участник и лот:

```sh
# Терминал 1
./auctioneer -n demo -f tests/data/simple.txt -w 300 -l shared.log
# Терминал 2
./participant -n demo -i 1
# Терминал 3
./lot -n demo -i 1
```

Для очередей замените имена на `auctioneer_mq`, `participant_mq`, `lot_mq`.
Нужна поддержка POSIX message queues в Linux.
Для другой конфигурации запустите отдельного рабочего для каждого участника
и лота. Нумерация с 1; имя `-n` одинаковое у всех процессов сеанса.
Для параллельных сеансов используйте разные имена и журналы.

## Параметры

| Ключ аукциониста | Значение |
| --- | --- |
| `-f файл` | Входные данные; без ключа - встроенный пример |
| `-l файл` | Журнал, по умолчанию `auction.log`; очищается после создания IPC |
| `-d мс` | Такт: 0-10000 мс; по умолчанию 200; 0 означает 1 мс |
| `-r 0` / `-r 1` | Резерв только у лидера / у текущего и прежних лидеров до закрытия; по умолчанию 0 |
| `-n имя` | 1-16 латинских букв, цифр или `_`; по умолчанию `demo` у независимых программ, имя из PID у версий с `fork` |
| `-w секунды` | Ожидание подключения: 1-300 с; по умолчанию 30 |
| `-h` | Справка |

Рабочие программы принимают `-n имя`, обязательный `-i номер` и `-h`.
Входной файл и журнал должны различаться, в том числе через ссылки.

## Входной файл

```text
2 1 1 2 1
100 0 1 0
150 1 2 1
20 10 5
```

Первая строка: число участников, лотов, одновременно открытых лотов,
интервал продления, правило отказа.
Затем для каждого участника: бюджет, стратегия, задержка, отказ.
Затем для каждого лота: начальная цена, шаг, длительность.

- Участники и лоты: 1-32; одновременно открытые лоты: 1-число лотов.
- Бюджет и начальная цена: 0-1000000; шаг: 1-1000000.
- Длительность и задержка: 1-1000 тактов; продление: 0-1000, 0 отключает его.
- Стратегия: 0 - один шаг, 1 - два шага.
- Правило отказа: 0 - все платят, 1 - отказ с повторным открытием.
- Отказ участника: 0 - платит, 1 - отказывается при включённом правиле отказа.

Числа разделяются пробельными символами; комментарии не поддерживаются.
Проверяются диапазоны, полнота и отсутствие лишних данных.
Размер файла должен быть меньше 16383 байт.

## Завершение и тесты

После закрытия всех лотов программа завершается. `Ctrl+C` / `SIGINT` и
`SIGTERM` любому подключённому процессу останавливают весь аукцион:
незавершённые лоты отменяются, резервы освобождаются, оплаченные покупки
сохраняются. Владелец ожидает рабочих и удаляет IPC ресурсы.
Коды выхода: `0` - успех, `1` - ошибка, `130` - SIGINT, `143` - SIGTERM.
Очистка и восстановление после SIGKILL не реализованы.

`make test` выполняет **138 проверок**: 72 сценария и 66 проверок ошибок.
Проверяются ставки, сроки, оба режима резервов, отказы, 32 участника и 32 лота,
сигналы, неверный ввод и удаление IPC. Журналы сохраняются в `tests/results/`.
Все проверки успешно пройдены в Debian 12 aarch64
с GCC 12.2.0, Make 4.3 и Python 3.11.2; сборка без предупреждений.

Код находится в `src/`, данные - в `data/` и `tests/data/`, проверки -
в `tests/check.py` и `tests/log_checks.py`.
`make clean` удаляет программы, `auction.log` и `tests/results/`.
