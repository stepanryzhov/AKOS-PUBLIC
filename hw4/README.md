## Быстрый запуск

Нужны компилятор C и `make`. Для автоматического запуска и тестов — Python 3.
Команды выполняются из `hw4`.

```sh
make
make run
make run DATA=tests/data/simple.txt DELAY=100 PORT=5001
make test
```

`make run` запускает сервер, всех участников, все лоты и одного наблюдателя.
В терминале отображается вывод наблюдателя, полный журнал сервера — `auction.log`.
`Ctrl+C` останавливает локальный запуск. `make help` показывает доступные таргеты.

## Отдельные процессы и работа по сети

Аукционист — сервер; каждый участник и каждый лот — самостоятельный клиент.
Наблюдатель получает полный поток событий и может запускаться в нескольких экземплярах.
Сначала запускается сервер, затем рабочие со всеми номерами из входного файла.
Например, для одного участника и одного лота в четырёх терминалах:

```sh
make server DATA=tests/data/simple.txt IP=0.0.0.0 PORT=5000 WAIT=300
make run-participant IP=127.0.0.1 PORT=5000 ID=1
make run-lot IP=127.0.0.1 PORT=5000 ID=1
make run-observer IP=127.0.0.1 PORT=5000
```

При запуске на разных компьютерах у клиентов вместо `127.0.0.1` указывается
IPv4-адрес компьютера с сервером; порт одинаковый. Общие файлы клиентам не нужны.
`0.0.0.0` у сервера означает прослушивание всех сетевых интерфейсов.
Для `make run` используйте локальный адрес, например `127.0.0.1`.

Те же программы можно запускать напрямую:

```sh
./auctioneer -a 0.0.0.0 -p 5000 -f data/default.txt -d 200 -r 0 -w 30 -l auction.log
./participant -a 127.0.0.1 -p 5000 -i 1
./lot -a 127.0.0.1 -p 5000 -i 1
./observer -a 127.0.0.1 -p 5000
```

Адрес `-a` и порт `-p` обязательны. `-h` выводит справку.
У сервера `-f` задаёт данные (без него встроенный пример), `-l` — журнал,
`-d` — длину такта 0–10000 мс (по умолчанию 200; 0 означает 1 мс),
`-r 0` — резерв только лидера, `-r 1` — сохранение резервов прежних лидеров до закрытия,
`-w` — ожидание первоначального подключения всех рабочих 1–300 секунд (30).
Для `make` доступны переменные `IP`, `PORT`, `DATA`, `DELAY`, `RULE`, `WAIT`, `LOG`, `ID`.

## Входные данные

Формат сохранён из HW3. Числа разделяются пробельными символами, комментариев нет:

```text
2 1 1 2 1
100 0 1 0
150 1 2 1
20 10 5
```

- Первая строка: участники, лоты, одновременно открытые лоты, продление, правило отказа.
- Затем для каждого участника: бюджет, стратегия, задержка, признак отказа.
- Затем для каждого лота: начальная цена, минимальный шаг, длительность.

Участников и лотов 1–32; одновременно открытых лотов 1–число лотов.
Бюджеты и начальные цены 0–1000000, шаг 1–1000000.
Длительности и задержки 1–1000 тактов, продление 0–1000; 0 отключает продление.
Стратегии: 0 — один шаг, 1 — два шага. Участник выбирает первый открытый лот,
в котором не лидирует и не исключён. Правило отказа 1 разрешает отказ участников
с признаком 1: лот открывается заново, отказавшийся исключается из него.
Размер файла меньше 16383 байт. Проверяются диапазоны, полнота и лишние данные.

## Подключение и завершение

Сервер начинает торги после подключения всех участников и лотов.
Наблюдатели подключаются в любой момент: сначала получают текущее состояние
всех лотов, бюджеты, резервы и статистику, затем все новые события.
Их отключение и повторный запуск не влияют на торги.

`Ctrl+C`/`SIGTERM` клиенту отключает только его. Для возвращения участника или лота
запустите программу снова с тем же номером. Сервер хранит подготовленную ставку,
цены, бюджеты и резервы; время модели при отсутствии рабочего приостанавливается
до его возвращения. Сетевое бездействие рабочего дольше 5 секунд также отключает его.
Ожидание повторного подключения не ограничено; сервер можно остановить сигналом.

После всех расчётов сервер передаёт итоги наблюдателям и команду завершения
всем подключённым клиентам. `SIGINT`/`SIGTERM` серверу отменяет незавершённые лоты,
освобождает резервы, сохраняет оплаченные покупки и завершает клиентов.
Сокеты закрываются, ожидание выхода клиентов ограничено двумя секундами.
Коды выхода: 0 — успех, 1 — ошибка, 130 — SIGINT, 143 — SIGTERM.
При аварийном исчезновении сервера клиенты завершаются при разрыве TCP или тайм-ауте.

## Код и проверки

Сервер хранит состояние в своей памяти и обслуживает неблокирующие сокеты через
`poll`. Один обработчик последовательно проверяет срок и применяет ставку, поэтому
порядок относительно закрытия однозначен. Общей памяти и семафоров между клиентами нет.
Команды ставки и закрытия обрабатываются сразу, без промежуточных флагов событий.
Клиент хранит только полученный снимок лотов и собственных средств; правила выбора
ставки находятся в клиенте, расчёты и резервирование — в серверной модели.
Обмен текстовый, с накоплением неполных строк TCP; структуры C напрямую не передаются.
У каждого соединения отдельный буфер вывода; переполнение отключает медленного клиента.
Одновременно поддерживается до 128 TCP-соединений, включая рабочих и наблюдателей.

`make test` проверяет обычные торги, сроки, продление, оба правила резервов, отказ,
нескольких наблюдателей, переподключение всех ролей с сохранением состояния,
остановку сервера, разбиение TCP-команд, занятый номер, тайм-аут запуска и ошибки аргументов.
Проверка журнала из HW3 сверяет шаг, сроки, бюджеты, резервы и итоги.
Журналы тестов сохраняются в `tests/results/`; `make clean` удаляет их и программы.
